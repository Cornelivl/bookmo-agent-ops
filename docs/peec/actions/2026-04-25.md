## Reusable, self-improving ranking system

Use this rubric each week before selecting work. The point is not to maximize Peec score alone; it is to choose tasks that can improve visibility while staying safe, measurable, and realistic for Bookmo.

Inputs:

1. Peec opportunity band: High / Medium / Low.
2. Gap band: nearly all missing / wide gap / partial gap / narrow gap.
3. Bookmo relevance: core / adjacent / weak.
4. Ability to act this week: same-day / this week / later.
5. Risk: low / medium / high.
6. Effort: small / medium / large.
7. Evidence quality: direct Peec action text with examples / category signal only / noisy.
8. Measurement readiness: baseline available / baseline absent but checkable / not currently measurable.

Decision lanes:

- quick win: high or medium opportunity, core relevance, low risk, small effort, can produce an artifact this week, and measurement is possible.
- needs planning: high or medium opportunity, core relevance, but requires page architecture, positioning, design, engineering, or competitive-claim review.
- needs upskilling/best-practices: opportunity exists, but execution depends on standards Bookmo should not fake, such as Wikipedia notability, community participation norms, YouTube production quality, schema/content SEO, or editorial outreach etiquette.
- repeatable/playbook: task can be templatized after one manual version works, such as content briefs, comparison-page checklists, source-report baselines, or weekly Peec deltas.
- blocked/manual: requires explicit human approval, outreach, public posting, page publishing, deployment, competitor claims, or Peec mutation.

Self-improvement loop:

- Before work: assign every candidate a lane and write the reason in one sentence.
- During work: create the smallest artifact that can be reviewed without publishing.
- After 7/14/30 days: compare Peec visibility changes against the baseline. If visibility improves, convert the task into a repeatable/playbook item. If it does not, record whether the failure was evidence quality, execution quality, indexing/crawl delay, or wrong intent.
- Each week: demote actions that remain noisy or blocked, promote actions with measurable movement, and update the next memo's top 3 accordingly.

## Owned opportunities

### Product-page opportunity

Peec indicates a high opportunity for owned product pages. The recommendation pattern is to build Bookmo pages that clearly explain the product in the language AI engines already associate with booking-agency software, artist management, logistics, contracting, and workflow automation.

Public examples surfaced by Peec include product-style pages on gigwell.com. Use these only as research references; do not copy structure, wording, claims, or positioning.

Recommended owned direction:

- Create a Bookmo product page or page section for music booking agencies.
- Make the page explicit about CRM, booking-agent workflow, deals, contracts, advancing, artist logistics, and AI-assisted follow-up.
- Add concise feature-to-use-case mapping: booking agents, agency owners, artist managers, and operations teams.
- Avoid unsupported competitor claims.

Lane: quick win for brief; needs planning for implementation/publishing.

### Comparison-page opportunity

Peec indicates a medium opportunity for comparison pages. Public examples surfaced by Peec include comparison content on systemonesoftware.com.

Recommended owned direction:

Lane: needs planning, then repeatable/playbook if the first brief is approved.
